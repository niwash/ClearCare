# A centre's events are typed rows from one route, and the page writes the words

A centre's record is the timeline of every public event about the centre. `GET /centres/{centre_id}/events` returns those events, newest first. An event is a `kind`, a `date` and that kind's fields, such as a price before and after, and it holds no sentence. The events are read from three views in db/V24 over rows that are already stored. `centre_inspection` has every report HIQA lists for the centre, joined to what was read from it by the hash of its file, because the date HIQA lists can differ from the date the report prints. A report that was read is an inspection or a thematic inspection (ADR-0032), dated as the report prints. A report that was not read is dated as HIQA lists it. When that date is before 2007 or after the day the report was published, the event has no date and is placed by its published date. `centre_register_change` has the register changes (ADR-0031), and the API serves those of one rules version, a constant in its repository. `centre_price_change` has each contract price that differs from the centre's price in the list before (ADR-0018). Events of one day come in a fixed order of kinds, which `api/openapi.yaml` gives.

The pipeline could have filled one event table for every kind. Inspections and prices are already stored, so the table would hold a copy of them, and the copy would have to be kept in step each time a report or a price list is loaded. The API could also have built a sentence for each event. The site's words are written in the web code, so the wording would be split between two code bases.

A new kind of event needs a view or a column, a record in the API's `events` package, a schema in `api/openapi.yaml` and its words on the page. The page has to say that a register change other than a registration is dated by the day we first saw it. The route carries no provider name without a CRO number, because the stored register changes leave those out. HIQA takes old reports off a centre's page. A report that was read before then is still an inspection on the timeline, with no published date. A file that HIQA lists under two names would be two events. `GET /centres/{centre_id}` now also gives the registration dates, the extra conditions and the Chief Inspector's note from the served snapshot, and the date of the list the contract price is from, because the centre's page shows the registration as it stands.
