# Google's coordinates are refreshed every 23 days and deleted at 30

The `geocode` stage fills `clearcare.centre_location` from Google's Geocoding API, after the register load on every daily run. Google's EEA Service Specific Terms, which apply to an Irish billing address, let the latitude and longitude it returns be cached for up to 30 consecutive calendar days, after which they must be deleted (section 6.2.1). Counting ages in UTC calendar days, whatever the time of day, the stage first deletes every point 30 or more days old, with or without a key and before asking Google anything. It then geocodes each centre in the served register that has no point, or one 23 or more days old, and stores only the point and `place_id` of an answer that passes its checks. A point stamped on day D is replaced by the run on day D+23, and the run on day D+30 deletes any point still in the table. RDS keeps seven days of automated backups, so a replaced point ages out of them at about the time of that deletion. A refresh that fails keeps the old point until the deletion, and the backups then hold it for up to seven days more.

Geocoding each centre once and keeping the point would send the fewest requests, but section 6.2.1 does not allow it. Refreshing at 30 days would keep the table within the limit while the backups held each old point seven days longer. Storing the geocoded address would catch a changed register address the next day rather than within 23 days, at the cost of a column V16 does not have and a second copy of the address to keep in step.

From now on, anything that reads the points must ignore those 30 or more calendar days old, because a day without a run leaves them in the table. The API will read them only through a view, which must leave them out by counting UTC dates the same way (ADR-0026). Manual dumps leave out the table's rows (`--exclude-table-data=clearcare.centre_location` in `infra/aws/README.md`), and after a restore the next run geocodes every centre again. Keeping RDS backups longer than seven days needs an earlier refresh, so the two change together.
