# Coordinates reach the map through a route only the site can call

The search page will show every centre a search matches as a pin on a Google map. The points are Google's geocoding results (ADR-0027), and Google's terms say what may be done with them. The EEA Service Specific Terms leave latitude and longitude out of what may not go on a map. Section 6.1 of their Geocoding API terms reads: "Other than latitude, longitude, and place_id, Customer may not use Google Maps Content from the Geocoding API With any Map." Section 6.2.1 lets the two values be cached "for up to 30 consecutive calendar days". The EEA Terms of Service, in section 3.3.2(a) (No Scraping), say that Customer will not "pre-fetch, index, store, reshare, or rehost Google Maps Content outside of the Services". We read a public API that answers coordinates as resharing them. So the public API still gives none, and one route, `GET /centres/points`, gives them only to the site's own server. It takes the search parameters of `GET /centres` and answers every matching centre that has a point in `clearcare.centre_point`, in name order: its ID, name, address and county, the latitude and longitude as stored, and `distance_m` when `near` is given. The answer has no pages and one order, so `page`, `page_size` and `sort` are refused. The caller sends the token the site shares with the API (ADR-0025) as `X-ClearCare-Token`, and names no account. The route answers 401 without the right token, and 503 while the deployment has none.

Putting the coordinates in the items of `GET /centres` needs no new route. But that API is public, so it would hand Google's points to anyone who asked, and a page holds 50 centres at most, so a map drawn from one page shows empty country where there are centres. Rounding the coordinates so that the public API could carry them puts the pin on the wrong building. A public route for the points alone gives the map every pin, and lets one request download every point ClearCare holds.

From now on the site's server asks for the points for every page that may draw the map and does not cache them, because the database's copy is the only one whose age is counted (ADR-0027). Since CCARE-230 that is the search page with nothing searched and every search with results: a wide screen shows the map beside the list, and the server cannot know the screen's width, so a narrow screen's list is sent points it does not draw until Map is chosen. The page gives them to the browser only to draw the map, and nothing else on the page uses them. A determined visitor can still read the pins a map shows them, as on any map. No CSV or other download carries coordinates, and no other answer of the API does. A deployment without the token has no map.
