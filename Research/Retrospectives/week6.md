# Week 6 Retrospective

## What went well

As a team, we made considerable progress on the website, including an overhaul of the UI and the start of initial user evaluations. We also improved the pricing data pipeline so that prices are downloaded automatically by the scheduler, obtained the maximum contract prices, and completed the interim report and presentation.

## What didn’t go well

We submitted the interim report late, and planning for the report and presentation could have been better. Some Pull Requests were too large to review efficiently, and we identified noticeable bugs on the website. We also faced difficulties sending the amenities data to the front end and missed some nursing homes because HIQA labelled them as “Disability Service”.

## What we will improve on

We will set clearer deadlines, keep better track of tickets, and address backlogs earlier. We will split repository changes into smaller, easier-to-review Pull Requests. We will also improve daily planning, coordinate report writing and presentations earlier, communicate more consistently, and maintain a clearer plan for tracking progress and future work.

## What we will do next

We will address visual bugs, continue user evaluations, and work on features such as geocoding and the comparison grid. We will progress labelling, comparison, and the promise trail for the centre page, while preparing the Gold Set to evaluate the LLM. We will also revise the architecture based on the mentor’s feedback, increase back-end development, and speed up data extraction so that more insights can be displayed on the front end.
